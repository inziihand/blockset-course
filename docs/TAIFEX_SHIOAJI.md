# 台指期優先：永豐金 Shioaji 介接規格

日期：2026-09-16。券商由使用者確認為永豐金／Shioaji。官方規格已查核；帳戶、SDK 版本、模擬環境及下列能力尚未實測。

## 1. 商品範圍與單位

| 商品 | 期交所代碼 | 每口每點價值 | 數量 | V1 範圍 |
| --- | --- | --- | --- | --- |
| 大台指期 | TX | TWD 200 | 整數口 | 月契約 |
| 小台指期 | MTX | TWD 50 | 整數口 | 月契約；週到期契約先不啟用 |
| 微型台指期 | TMF | TWD 10 | 整數口 | 月契約 |

三者最小跳動皆為 1 指數點，採現金交割。來源：[TX](https://www.taifex.com.tw/cht/2/tX)、[MTX](https://www.taifex.com.tw/cht/2/mTX)、[TMF](https://www.taifex.com.tw/cht/2/tMF)。

平台設計：

- `quantity_unit=CONTRACT`、`price_unit=INDEX_POINT`、`settlement_currency=TWD`；UI 分別標示口、點、新臺幣，不沿用 BTC／USD Size 欄位。
- 乘數用於每點風險、名目金額及估值。相同點數變化下 1 TX、4 MTX、20 TMF 的金額敏感度相當，但不可據此宣稱保證金必然自動互抵。
- 線性期貨未扣費估值：`方向符號 × 口數 × 每點價值 × (評價價 - 基準價)`。基準價明示開倉均價或結算價；券商權益與結算損益為對帳依據，避免重複計入逐日結算。
- 風控先使用 gross 口數、TWD／點曝險及可用資金。不同到期月即使淨曝險接近 0，仍有價差風險，不能全部抵消。

## 2. 交易日、日夜盤與到期

上述商品一般盤為 08:45–13:45，夜盤 15:00–次日 05:00；到期契約最後交易日一般盤到 13:30，該到期契約沒有其後的夜盤。盤後交易屬於下一個一般交易時段所屬交易日，ROD 為當盤有效。來源：[商品規格](https://www.taifex.com.tw/cht/2/tX)、[盤後交易制度](https://www.taifex.com.tw/cht/4/aHIntroduction)。

平台設計：

- 不把「現在日期 + 1」當作夜盤交易日。使用版本化期交所行事曆、例外公告及券商狀態；連假、週末、颱風休市必須有 fixtures。
- 分開 `calendar_date`、`trading_date`、`session_id`、`session_phase`；盤前收單、連續交易、盤間休息、到期停止與休市各有狀態。
- V1 只允許已驗證的一般／盤後連續交易時段送單；盤前收單及預約單留待獨立驗收，不因 SDK 接受就啟用。
- ROD 跨盤後不得當成有效掛單延續；查詢回報確認到期／取消，不能靠時鐘直接宣稱已撤單。
- 月份必須解析為實際到期契約。主連／近月 alias 可用於選擇，但 intent 必須保存當次到期日、SDK code 與 full code；重啟不得重新解析成不同月份。
- MTX 存在非月契約序列，不能僅以年月作 instrument identity；未啟用序列明確顯示不支援。
- V1 不自動換月；提供到期警示、禁止太接近到期的新開倉及明確退出政策。時間門檻留待策略設定，不捏造預設交易規則。

## 3. Shioaji 對應與待驗證事項

| 平台語意 | 官方 SDK／回報語意 | 實作要求 |
| --- | --- | --- |
| 期貨帳戶 | FutureAccount／指定 futopt account | 明確綁定帳戶，不能依登入後第一個預設帳戶 |
| 限價／市價／一定範圍市價 | LMT／MKT／MKP | 價型與 TIF 合法組合由 capability 驗證 |
| 當盤／立即成交否則取消／全部成交否則取消 | ROD／IOC／FOK | 不把 ROD 當跨日 GTC |
| 開倉／平倉／自動／當沖 | New／Cover／Auto／DayTrade | enum 名稱以鎖定 SDK 版本為準；V1 明確開平、停用當沖 |
| 委託／成交識別 | id、seqno、ordno、trade_id、exchange_seq | Adapter 持久化映射，不假設所有 ID 永久全域唯一 |

官方說明：[期貨下單](https://sinotrade.github.io/tutor/order/FutureOption/)、[委託與成交回報](https://sinotrade.github.io/tutor/order/order_deal_event/futures/)。

執行設計與驗證要求：

- Python SDK 直接由 Worker 載入。先釘選穩定版本，核對 Python／CPU／OS wheel、CA 憑證及模擬登入；不因官方文件同時提供 HTTP Server 就再增加一個中介服務。
- API Key、Secret、CA 檔案與密碼使用服務端秘密設定。憑證只讀掛載，不包進映像、不提交、不存 Firestore、不將 SDK 原始物件直接打入 log。
- 只查行情／帳戶不表示已取得交易權限。SDK 下單文件要求登入與 CA；簽署、測試及模擬與正式差異要逐項記錄。[簽署與測試](https://sinotrade.github.io/tutor/prepare/terms/)、[登入](https://sinotrade.github.io/tutor/login/)
- Callback 註冊／訂閱順序、重連後補訂閱、帳戶查詢額度、session 數量限制均列入 P2 實測；限制值不以猜測寫死。
- 確認 SDK `Trade` 是否僅為程序內物件，以及重啟後如何重建改撤單目標、可取得多長的委託／成交歷史。若無法證明未知委託結果，停留對帳阻塞。
- 不把 `custom_field` 當作券商保證的 client idempotency key。是否完整回傳、唯一、可查詢及可跨 session 保留，全部先驗證。
- 即使 SDK 回傳成功，仍需券商委託／成交證據。部分成交、撤單失敗、晚到成交、斷線後重複回報要分別回放。
- 回報先按帳戶、交易日／盤別、券商映射及成交識別去重；實際唯一鍵須用鎖定版本與跨日樣本驗證，不能單用 `ordno` 截斷猜測。

## 4. 平倉、部分成交與未知寫入

平倉採經驗證的 Cover 指示，讀取最新可平數量、扣除未完成平倉保留量，再建立平倉 intent。不得以 Auto 或單純反向 BUY／SELL 作為「保證只減倉」的替代。

`Cover` 是否在所有盤別、超額平倉、同時外部交易及重連情境下都會拒絕反向開倉，必須驗收。未證實的 `native_reduce_only` 保持 UNVERIFIED；若要求的保障無法滿足，拒絕該能力，不在前端宣稱 Reduce-only。

單腿 IOC 部分成交：累積真實成交、取消／到期殘量確認後再決定下一步，不自動補足目標。FOK 是成交條件而非成交保證；價格、流動性或交易規則不滿足仍可能整筆不成交。

市價與積極限價是可選執行政策。V1 先驗證 LIMIT + SESSION／IOC，MKT、MKP、FOK 各自經 capability 測試後開放，不把「緊急平倉」等同無條件市價重送。[委託單種規則](https://www.taifex.com.tw/cht/4/oamIntroduction)

任何送單／改單／撤單結果不明，先保存 intent 與查詢證據。接著查狀態、成交及部位；有矛盾就停止自動交易、保留監控，不以重新登入或重啟清除問題。

## 5. 資金、保證金與外部部位

- 顯示券商回報的權益、可用資金、原始／維持保證金與風險資訊，全部帶幣別、觀測時間及可用性。
- 保證金金額會變動；期交所公告與券商實際要求分開。試算只作預檢，不能取代券商授信／風控，也不硬編今天的每口金額。[期交所保證金公告](https://www.taifex.com.tw/cht/5/indexMargingDetail)
- 手續費、期交稅、結算損益及未實現損益分欄；費率與計費基準版本化，未驗證數值不當作真實淨損益。
- 初次啟動只管理平台能證明歸屬的部位。外部手動部位不因商品與方向相同就自動接管。
- V1 不支援有策略時任意外部交易。觀測到外部委託、平倉或增減量，標記對帳差異並保留 account-wide 風險，等待操作員處理。
- 未來「指定部位接管」是獨立流程，需歸屬快照、審核命令、設定及稽核；不要求使用者為了啟動測試先任意清空正式帳戶。

## 6. 驗收順序

Fake Broker 與歷史回放 → Shioaji 模擬唯讀 → 模擬單腿交易 → 日夜盤／重啟故障驗收 → 明確策略規則 → 正式唯讀 → 另行授權的最小量正式驗收。

台指期 MVP 完成才處理 TXO、組合單與自動換月。正式驗收可考慮 TMF 作較小金額曝險的商品，但商品、口數與時間仍需明確指定；此規劃本身不授權任何下單。
